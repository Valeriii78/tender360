# ЄДР Crawler

Краулер для завантаження Єдиного державного реєстру України з data.gov.ua.

## Що завантажує

| Джерело | Що містить | Оновлення |
|---|---|---|
| data.gov.ua (ЄДР) | Юридичні особи: назва, ЄДРПОУ, адреса, засновники, керівники, КВЕДи, стан | Щотижня |
| data.gov.ua (ФОП) | Фізичні особи-підприємці | Щотижня |

## Схема БД (нові таблиці)

| Таблиця | Що зберігає |
|---|---|
| `companies` | Основні дані компаній та ФОП |
| `persons` | Фізичні особи (засновники, керівники, бенефіціари) |
| `company_persons` | Зв'язки компанія↔особа з роллю та часткою |
| `company_kveds` | КВЕДи компаній |
| `company_history` | Changelog змін (старе → нове значення) |
| `sanctions` | Санкційні списки РНБО |
| `court_cases` | Судові справи |
| `public_finances` | Фінансова звітність |

## Запуск

```bash
npm install
cp .env.example .env   # вставити DATABASE_URL

# Повне завантаження (одноразово, ~2–4 год)
npm run full

# Постійне оновлення (раз на добу)
npm run watch

# Перевірка конкретного ЄДРПОУ
npm run check 23937436
```

## Режими

**full** — завантажує ZIP-дампи з data.gov.ua, розпаковує, парсить XML потоково, зберігає в БД. Повторний запуск пропускає файли які вже є.

**watch** — той самий full, але в циклі раз на 24 год. Автоматично підхоплює нові дампи.

**check** — real-time запит до API МінЮсту по конкретному ЄДРПОУ.

## Важливо

- Файли дампів великі (1–5 GB після розпакування)
- Парсинг потоковий — RAM не переповнюється
- Дублі не створюються — upsert по ЄДРПОУ
- Зміни записуються в `company_history` (changelog)
- Тимчасові файли видаляються після обробки

## Наступні кроки

Після запуску ЄДР-краулера:
1. **Backend API** — ендпоінти для пошуку по компаніях та особах
2. **Граф зв'язків** — побудова зв'язків по засновникам та адресам
3. **Судовий реєстр** — краулер reyestr.court.gov.ua
4. **Санкції РНБО** — краулер sanctions.nsdc.gov.ua
